### 2. Анализ архитектуры монолитного приложения

- Язык: GO
- Бд: Postgres
- Архитектура: монолитная
- Взаимодействие: синхронное
- Масштабируемость: ограниченная, из-за того что монолит придётся масштабировать целиком

### 3. Определение доменов и границы контекстов

- Управление устройствами

- Подписки, оплата
- Ui:
    - Мобильное приложение
  - Веб-приложение.

- Функциональность очень скудная
- Масштабируемость ограниченная

# **Задание 6. Разработка MVP**
Создан [docker-compose](./apps/docker-compose-microservice.yml) и DockerFile в соответствующих микросервисах

Были созданы два микросервиса с базовой функциональностью

[StatisticsService](./apps/statistics-service) - java + spring boot   
Сбор статистики

[ScheduleService](./apps/schedule-service) - go   
Комплексные сценарии управления

Предполагается что монолитом является [smart_home](./apps/smart_home). Мы постепенно внедряем новые микросервисы. В монолите остались функции запроса температуры, а в новых микросервисах были реализованы статистика и создание сценариев. Сервисы были выполнены на разных языках, чтобы выполнить поставленное задание, но в реальности выбор технологии будет сильно упираться в компетенции команды разработчиков.

Был добавлен nginx для распределения запросов, чтобы фронтэнд мог обращаться по одному адресу. В зависимости от пути запросы будут перенаправлены в соотвествующий сервис

Команда для запуска контейнеров
```markdown
docker-compose -f .\docker-compose-microservice.yml up --build -d
```
